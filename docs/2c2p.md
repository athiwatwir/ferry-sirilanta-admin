# 2C2P Payment Integration

เอกสารสรุปการชำระเงินผ่าน **2C2P Payment Gateway (API v4.3)** ในโปรเจกต์ Ferry Sirilanta Admin

อ้างอิงหลัก:

- [Sandbox Setup](https://developer.2c2p.com/docs/sandbox-setup)
- [Payment Token Request](https://developer.2c2p.com/docs/api-payment-token-request-parameter)
- [Payment Channels](https://developer.2c2p.com/docs/reference-payment-channels)
- [Prepare JWT](https://developer.2c2p.com/recipes/prepare-request-payload-with-jwt)
- [Payment Response Backend](https://developer.2c2p.com/docs/api-payment-response-back-end-parameter)

## สรุปภาพรวม

โปรเจกต์ใช้แบบ **Hosted Payment Page** (Redirect):

1. Backend เรียก **Payment Token API**
2. ได้ `webPaymentUrl` + `paymentToken`
3. Redirect ผู้ใช้ไปหน้าชำระของ 2C2P
4. หลังชำระ 2C2P เรียกกลับมาที่
   - `frontendReturnUrl` (browser)
   - `backendReturnUrl` (server-to-server)

Authentication ของ API ใช้ **JWT (HS256)** ลงนามด้วย Secret Key ของ merchant

## Environment / Config

โปรเจกต์นี้ใช้ **2 Merchant ID**:

| Env | ค่าตัวอย่าง | ใช้เมื่อ |
| --- | --- | --- |
| `MERCHANT_ID_CREDIT` | `014012023008685` | ชำระด้วยบัตร (`CC`) |
| `MERCHANT_ID_ETC` | `014022023008685` | QR / Wallet / ช่องทางอื่น |

ตั้งค่าใน `.env`:

```env
TWOC2P_SANDBOX=true
MERCHANT_ID_CREDIT=014012023008685
MERCHANT_ID_ETC=014022023008685
TWOC2P_SECRET_KEY=                 # secret ร่วม (ถ้ามีตัวเดียว)
# TWOC2P_SECRET_KEY_CREDIT=        # หรือแยกตาม merchant
# TWOC2P_SECRET_KEY_ETC=
TWOC2P_CURRENCY_CODE=THB
TWOC2P_PAYMENT_CHANNELS=CC,THQR,DPAY
```

| Key | ความหมาย |
| --- | --- |
| `MERCHANT_ID_CREDIT` / `TWOC2P_MERCHANT_ID_CREDIT` | **บังคับสำหรับบัตร** |
| `MERCHANT_ID_ETC` / `TWOC2P_MERCHANT_ID_ETC` | **บังคับสำหรับช่องทางอื่น** |
| `TWOC2P_SECRET_KEY` | Secret ร่วม (fallback) |
| `TWOC2P_SECRET_KEY_CREDIT` | Secret เฉพาะ credit merchant (ถ้ามี) |
| `TWOC2P_SECRET_KEY_ETC` | Secret เฉพาะ etc merchant (ถ้ามี) |
| `TWOC2P_SANDBOX` | `true` = sandbox, `false` = production |
| `TWOC2P_CURRENCY_CODE` | ค่าเริ่มต้น เช่น `THB` |
| `TWOC2P_PAYMENT_CHANNELS` | ช่องทาง default คั่นด้วย comma |
| `TWOC2P_BASE_URL` | override base URL |

Service จะเลือก merchant อัตโนมัติ:

- `paymentChannel` เป็นกลุ่มบัตรเท่านั้น (`CC`, `CSTOKEN`, `GCARD`) → **CREDIT**
- มีช่องทางอื่นปนอยู่ → **ETC**
- หรือส่ง `merchantProfile` เองเป็น `credit` / `etc`

Wallet Top up ด้วยบัตร ใช้ `merchantProfile = credit` ชัดเจน

หลังแก้ `.env` รัน:

```bash
php artisan config:clear
```

### รับ Merchant ID จากไหน

1. ติดต่อ 2C2P / account manager เพื่อขอ Sandbox หรือ Production credentials
2. มักได้แยกเป็น merchant สำหรับบัตร และ merchant สำหรับช่องทางอื่น
3. ใส่ Secret Key ให้ถูกคู่กับแต่ละ merchant (หรือใช้ตัวร่วมถ้า 2C2P ออกมาแบบนั้น)

### Base URL

| Environment | Base URL |
| --- | --- |
| Sandbox | `https://sandbox-pgw.2c2p.com` |
| Production | `https://pgw.2c2p.com` |

UI หน้าชำระ (sandbox): `https://sandbox-pgw-ui.2c2p.com/...`

## Authentication (JWT)

ทุก request/response สำคัญใช้ JWT:

1. สร้าง JSON payload
2. ลงนาม HS256 ด้วย Secret Key
3. ส่งใน body:

```json
{ "payload": "<jwt-token>" }
```

4. Response สำเร็จมักเป็น:

```json
{ "payload": "<jwt-token>" }
```

จากนั้น decode JWT ด้วย Secret Key เดิม

Service ในโปรเจกต์มีเมธอด:

- `encodeJwt(array $payload): string`
- `decodeJwt(string $jwt): array`
- `decodeRequestPayload(?string $payload): array`

Header ที่ใช้ตอนเรียก API:

- `Content-Type: application/json`
- `Accept: text/plain` (ตาม recipe ของ 2C2P)

## Payment Token API

Endpoint:

```http
POST {BASE_URL}/payment/4.3/paymentToken
```

### Request สำคัญ

| Field | บังคับ | หมายเหตุ |
| --- | --- | --- |
| `merchantID` | ใช่ | จาก config |
| `invoiceNo` | ใช่ | เลขใบแจ้งหนี้ unique ของเรา (max 50) |
| `description` | ใช่ | คำอธิบายรายการ |
| `amount` | ใช่ | จำนวนเงิน |
| `currencyCode` | แนะนำ | เช่น `THB` |
| `paymentChannel` | ไม่บังคับ | array เช่น `["CC"]` — ว่าง = ทุกช่องทางที่ merchant เปิด |
| `frontendReturnUrl` | แนะนำ | URL กลับหลังชำระ (browser) |
| `backendReturnUrl` | แนะนำ | URL notify ฝั่ง server |
| `request3DS` | ไม่บังคับ | `Y` / `F` / `N` (default ใน service = `Y`) |
| `userDefined1..5` | ไม่บังคับ | เก็บ metadata ของระบบเรา |

### Response สำเร็จ (หลัง decode JWT)

| Field | ความหมาย |
| --- | --- |
| `respCode` | `0000` = สำเร็จ |
| `respDesc` | คำอธิบาย |
| `paymentToken` | token ใช้ต่อใน Direct API / SDK |
| `webPaymentUrl` | URL หน้าชำระ — redirect ผู้ใช้ไปที่นี่ |

## วิธีเรียกใช้ Service

```php
use App\Services\TwoC2PService;
use App\Exceptions\TwoC2PException;

try {
    $payment = app(TwoC2PService::class)->createPaymentToken([
        'invoiceNo' => 'INV' . time(),
        'description' => 'Wallet Top Up',
        'amount' => 1000,
        'currencyCode' => 'THB',
        'paymentChannel' => ['CC'],
        'frontendReturnUrl' => route('payment.2c2p.frontend'),
        'backendReturnUrl' => route('payment.2c2p.backend'),
        'userDefined1' => 'wallet_topup',
    ]);

    return redirect()->away($payment['webPaymentUrl']);
} catch (TwoC2PException $e) {
    // $e->getMessage(), $e->respCode, $e->payload
}
```

เมธอดที่มีใน `TwoC2PService`:

| Method | ใช้ทำอะไร |
| --- | --- |
| `createPaymentToken()` | ขอ token + webPaymentUrl |
| `createHostedPaymentUrl()` | ขอแล้วคืนแค่ URL |
| `inquirePayment($invoiceNo)` | เช็คสถานะรายการ |
| `isPaymentSuccessful($respCode)` | `true` ถ้า `0000` |
| `makeInvoiceNo($prefix)` | สร้าง invoice แบบสุ่ม |

## Payment Channels (ช่องทางที่แสดงบนหน้าชำระ)

ช่องทางที่ลูกค้าเห็น =  

**ช่องทางที่ 2C2P เปิดให้ merchant** ∩ **ค่า `paymentChannel` ที่เราส่ง**

### ถ้าไม่ส่ง `paymentChannel`

หน้าชำระจะโชว์ทุกช่องทางที่ merchant เปิดไว้

### ถ้าส่ง `paymentChannel`

จะจำกัดเฉพาะ group ที่ระบุ เช่น:

```php
'paymentChannel' => ['CC']              // เฉพาะบัตร
'paymentChannel' => ['CC', 'THQR']      // บัตร + PromptPay QR
'paymentChannel' => ['CC', 'THQR', 'DPAY']
```

หรือผ่าน `.env`:

```env
TWOC2P_PAYMENT_CHANNELS=CC,THQR,DPAY
```

### Group Code ที่ใช้บ่อย

| Group Code | ความหมาย |
| --- | --- |
| `CC` | Credit/Debit Card (Visa, Mastercard, JCB, Amex, UnionPay…) |
| `THQR` | Thai QR เช่น PromptPay |
| `DPAY` | Digital Payment / E-wallet |
| `QR` / `QRC` / `CSQR` | QR อื่นๆ |
| `IPP` | ผ่อนชำระ (Installment) |

รายละเอียดเต็ม: [Payment Channels](https://developer.2c2p.com/docs/reference-payment-channels)

### ในโปรเจกต์ตอนนี้

Wallet Top up บังคับบัตร:

```php
'paymentChannel' => ['CC'],
```

ดังนั้นหน้า 2C2P จะเน้นกลุ่มบัตร (ตามที่ merchant เปิดไว้)

## Callbacks / Routes

| Route | Name | วิธีเรียก | หน้าที่ |
| --- | --- | --- | --- |
| `/payment/2c2p/frontend` | `payment.2c2p.frontend` | GET/POST | กลับจากหน้าชำระ แสดงผลให้ user |
| `/payment/2c2p/backend` | `payment.2c2p.backend` | POST | notify จาก 2C2P (server) |

CSRF ถูกยกเว้นไว้ใน `bootstrap/app.php` สำหรับทั้งสอง path

### กัน logout ตอน Cancel / Back จากหน้าชำระ

2C2P มัก **POST กลับมาแบบ cross-site** ทำให้ cookie session (`SameSite=Lax`) ไม่ถูกส่ง  
Laravel จะสร้าง session ว่างแล้ว `Set-Cookie` ทับตัวเดิม → ผู้ใช้เหมือนถูก logout

แก้ในโปรเจกต์แล้ว:

1. `PreserveSessionOnCrossSiteReturn` — ถ้า request ไป `/payment/2c2p/frontend` **ไม่มี** session cookie เดิม จะไม่เขียน session cookie ทับ
2. หน้า bridge `resources/views/payment/2c2p-return.blade.php` — พาไปปลายทางด้วย top-level GET
3. ส่งสถานะผ่าน query (`payment`, `payment_msg`) แล้วหน้า wallet แปลงเป็น flash

> Production ที่เป็น HTTPS ทั้งระบบ สามารถตั้ง `SESSION_SAME_SITE=none` + `SESSION_SECURE_COOKIE=true` เพิ่มได้ แต่ local HTTP ใช้วิธีด้านบนปลอดภัยกว่า

### Backend / Frontend response ที่สนใจ

| respCode | ความหมาย | ต้องทำอะไร |
| --- | --- | --- |
| `0000` | ชำระสำเร็จ | อนุมัติทันที |
| `2000` | หน้าชำระจบแล้ว ให้ inquiry | เรียก Payment Inquiry |
| `2001` | กำลังดำเนินการ | retry inquiry |
| `2002` | หา transaction ไม่เจอ | retry / fallback |
| `0003` / `2003` | ยกเลิก / ล้มเหลว | ไม่อนุมัติ |

`TwoC2PController` (frontend + backend):

1. decode `paymentResponse` / `payload` — รองรับ **JWT**, **Base64URL JSON**, raw JSON  
   (frontend มักส่ง Base64 JSON ไม่ใช่ JWT)
2. ถ้า `respCode = 2000/2001` → `resolveCompletedPayment()` ทำ Payment Inquiry (+ retry)
3. หา wallet top-up จาก `userDefined3` หรือ `invoiceNo` รูปแบบ `WT{uuid}`
4. ถ้าสำเร็จ (`0000`) → `isapproved = Y` และเพิ่ม `wallet_balance`

#### จุดที่เคยพัง (แก้แล้ว)

1. **Decode ผิดรูปแบบ**  
   Frontend ส่ง Base64 JSON → เคย error `Invalid JWT format` → ไม่อนุมัติ  
   แก้: `TwoC2PService::decodeRequestPayload()` รองรับหลายรูปแบบ

2. **Inquiry ทับสถานะผิด**  
   Frontend ได้ `2000` แต่ inquiry ได้ `2002` แล้วเอา `2002` ไปทับ → ไม่อนุมัติ  
   แก้: retry inquiry ด้วย `invoiceNo` / `paymentToken` และถ้า frontend เป็น `2000` แต่ inquiry ไม่ชัด → ถือว่าสำเร็จแล้วอนุมัติ

3. **Backend เข้า local ไม่ได้**  
   `php artisan serve` บน localhost รับ backend notify จาก 2C2P ไม่ได้  
   จึงพึ่ง frontend return + inquiry / fallback เป็นหลักตอนทดสอบ local

4. **เก็บ paymentToken**  
   ตอนสร้าง payment token จะ `rememberPaymentToken()` ไว้ใน cache เพื่อ inquiry ด้วย token ตอนกลับมา

## Flow ในระบบ: Wallet Top up

หน้า: `resources/views/pages/agent-account/show.blade.php`

ผู้ใช้เลือกได้ 3 แบบ:

1. **โอนเงิน / แนบสลิป**  
   - อัปโหลดสลิป + จำนวนเงิน  
   - บันทึก `agent_account_transections` สถานะรออนุมัติ (`isapproved = N`)  
   - admin อนุมัติทีหลัง

2. **บัตรเครดิต / เดบิต (2C2P)**  
   - ใช้ `MERCHANT_ID_CREDIT`  
   - `paymentChannel = ['CC']`  
   - description ขึ้นต้น `[CARD]`  
   - frontend/backend สำเร็จ → **อนุมัติอัตโนมัติ** (`isapproved = Y`) + เติม wallet

3. **QR / PromptPay / Wallet (2C2P)**  
   - ใช้ `MERCHANT_ID_ETC`  
   - `paymentChannel` จาก `TWOC2P_ETC_PAYMENT_CHANNELS` (default `THQR,DPAY,QRC,CSQR`)  
   - description ขึ้นต้น `[ETC]`  
   - หน้า 2C2P โชว์ช่องทางตามที่ merchant ETC เปิดไว้ ∩ channels ที่ส่ง  
   - frontend/backend สำเร็จ → **อนุมัติอัตโนมัติ** + เติม wallet

> ไม่ต้องสร้างหน้าเลือก Visa/PromptPay เอง — ใช้หน้า Hosted ของ 2C2P

### Invoice format ของ Wallet Top up

```text
WT + {uuid โดยตัดขีดออก}
ตัวอย่าง: WT019fa3238bb7728e95a53385896c5f7d
```

ใช้ map กลับไปหา `agent_account_transections.id` ใน callback  
(และใช้ `userDefined3` = transaction uuid เป็น fallback)

## Payment Inquiry

Endpoint:

```http
POST {BASE_URL}/payment/4.3/paymentInquiry
```

ใช้เช็คสถานะเมื่อ frontend ได้ `2000` / callback ไม่ครบ / ต้องการยืนยันซ้ำ:

```php
$result = app(TwoC2PService::class)->inquirePayment($invoiceNo, 'credit', $paymentToken);
// หรือผ่าน resolveCompletedPayment() ที่ controller เรียกอยู่แล้ว
$payload = app(TwoC2PService::class)->resolveCompletedPayment($frontendPayload, 'credit');
```

เมธอดที่เกี่ยวข้อง:

| Method | ใช้ทำอะไร |
| --- | --- |
| `decodeRequestPayload()` | ถอด JWT / Base64 JSON / JSON |
| `needsPaymentInquiry()` | `true` ถ้า `2000` / `2001` |
| `resolveCompletedPayment()` | inquiry + retry + fallback จาก frontend `2000` |
| `rememberPaymentToken()` / `recallPaymentToken()` | เก็บ/ดึง token จาก cache |
| `isPaymentSuccessful()` | `true` ถ้า `0000` |

## Response / Error ที่พบบ่อย

| อาการ | สาเหตุที่พบบ่อย | แก้ |
| --- | --- | --- |
| `2C2P response missing payload` | API ส่ง error JSON ตรงๆ ไม่มี wrapper `payload` | อ่าน `respCode`/`respDesc` จาก body (service รองรับแล้ว) |
| `Invalid Request (9042)` | Merchant ID ไม่คู่ Secret Key / request ไม่ถูกต้อง | ตรวจ `.env` คู่ merchant+secret |
| `2C2P is not configured` | ยังไม่ตั้ง `TWOC2P_SECRET_KEY` | ใส่ค่าใน `.env` แล้ว `php artisan config:clear` |
| ไม่เห็นช่องทางบางอันบนหน้าชำระ | merchant ยังไม่เปิด channel หรือถูกจำกัดด้วย `paymentChannel` | เปิด channel กับ 2C2P / ปรับ `TWOC2P_PAYMENT_CHANNELS` |
| Callback ไม่เข้า | URL เป็น localhost / CSRF / firewall | ใช้ tunnel (เช่น ngrok) สำหรับ backendReturnUrl ตอนทดสอบจริง |

หลังแก้ `.env` ควรรัน:

```bash
php artisan config:clear
```

## แผนขยายการใช้ Service

`TwoC2PService` ออกแบบให้ใช้ซ้ำได้ เช่น:

- ชำระค่าตั๋ว booking
- Top up wallet (ทำแล้ว)
- ชำระ invoice อื่นๆ

แนวทางเดียวกัน:

1. สร้าง/อ้างอิงรายการในระบบ + `invoiceNo` unique
2. เรียก `createPaymentToken()`
3. redirect ไป `webPaymentUrl`
4. ที่ callback ตรวจ `respCode` แล้วอัปเดตสถานะธุรกิจของระบบ

---

## หมายเหตุเรื่อง `PAYMENT_URL`

ในโปรเจกต์ยังมี `PAYMENT_URL` (env) สำหรับลิงก์ชำระตั๋วเดิม (`components/booking/dropdown-payment`)

ส่วน **Wallet Top up ด้วยบัตร** ใช้ `TwoC2PService` โดยตรง ไม่ผ่าน `PAYMENT_URL` แล้ว
